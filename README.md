# 有序映射与迭代器语义（从 0 实现）

仓库里只有本说明、`samples/**` 与 `.gitignore`：引擎、入口、页面与测试都从零写。预演时有人在遍历中
改集合、程序抛了异常，两拨人为「该不该抛」吵到会上——这次把口径写死。

## 1. 范围

交付物（仓库根）：`rangemap/` 包（Python 3.13 标准库，`python -m rangemap` 是入口）、`web/` 下的区间
页面（原生 HTML + 内联 SVG，无构建、双击可开）、`unittest` 测试（用例只读 `samples/`）。

```text
python -m rangemap run  <键文件> <操作文件> <转录文件>
python -m rangemap page <键文件> <操作文件> <页面文件> [--trace <轨迹文件>]
```

做：按码点序的键值映射；增删改查；四种开闭的范围查询；按序遍历与遍历中修改的失效检测；百万键规模；
一页区间与失效时刻的页面。
不做：持久化、并发、序列化协议、网络与 CDN、第三方依赖与构建、非法输入容错（样例保证合法）、
非文本键值、按值查询。

## 2. 口径与公式

- **键与值**：都是不含空白、非空、不以 `#` 开头的 UTF-8 token；样例不用 `-`（缺失记号）。键按
  Unicode 码点比较（Python 字符串的 `<`）：不折叠大小写、不做规范化、不看 locale——`d1<d10<d2`、
  `Z<a`、`波`(U+6CE2)`<阿`(U+963F)。键唯一，值可重复。
- **可见性**：`set` 覆盖、`del` 删除，命令返回即生效，后面的 `get`、`range`、`walk` 立刻看到；没有事务、
  版本号与延迟删除。值没变的 `set`、删不存在的键都不算改动（`changed=0`）。
- **范围**：`range <mode> <lo> <hi>`，`mode` 取 `[]`、`[)`、`(]`、`()`，两端闭含开不含；`lo`、`hi` 是键值、
  不要求存在；命中按码点升序逐条给出。`lo > hi` 恒空；`lo == hi` 只有 `[]` 且该键存在时命中；空结果是
  合法结果（`count=0`）。
- **遍历**：`walk` 打开一次升序遍历，位置记「上一个产出的键」，`step` 产出比它大的最小键（第一次产出
  最小键），走完给 `step end` 并关掉；同一时刻最多一个遍历。不复制快照——每步都看实时集合，集合一变
  位置就不可靠。
- **失效**：遍历打开期间，第一次真正改动集合的操作（新增键、改值、删存在的键）立刻让它失效，那一刻的
  转录写 `walk=stale`；失效的遍历仍占名额，`walk` 给 `E_WALK_OPEN`，先用一次 `step` 拿 `E_ITER_STALE`
  才关掉、之后才能重新 `walk`。`get`、`range`、值没变的 `set`、删不存在的键、继续 `step` 都允许在
  遍历中做。

## 3. 状态机与数据结构

映射 = 键到值的字典 + 按键升序的索引；百万键下 `range` 要直接定位到区间两端，不能从头逐键比较。遍历
只有三个状态：

```text
idle --walk--> open --step 到底--> idle
open --第一次真正改动集合--> stale --step（E_ITER_STALE）--> idle
```

`open` 与 `stale` 都算「有打开的遍历」：期间再 `walk` 报 `E_WALK_OPEN`；`idle` 时 `step` 报 `E_NO_WALK`。

## 4. 输入输出与文件格式

本节文件一律 UTF-8、`\n`、末行有换行；空行与 `#` 开头的行忽略。

**4.1 键文件** `samples/keys/<名>.keys`：每行一个键，顺序任意；重复键只算一个；初始值就是键自身。

**4.2 操作文件** `samples/scripts/<名>.ops`：每行一条，字段用空白切分：
`set <键> <值>`、`del <键>`、`get <键>`、`range <mode> <lo> <hi>`、`walk`、`step`。

**4.3 转录**：`run` 的输出，与 `samples/expected/<同名>.out` 逐字节相同。每个操作一段，`range` 的命中
紧随其后、两空格缩进、升序（下面是节选）：

```text
set k1 v1 size=3 changed=1 walk=idle    # size 是执行后的键数
del k9 size=3 changed=0 walk=live       # walk 取 idle|live|stale
get k1 = v1                             # 缺失写 get k1 = -
range [) k1 k9 count=2
  k1 v1
  k4 v4
walk size=3                             # 打开遍历时的键数
step k1 v1                              # 每步一个键；走完写 step end
error E_ITER_STALE op=set key=k1        # 失效后的第一次 step
```

报错只结算这一条，脚本继续跑，`run` 的退出码仍是 0；同一份输入跑两遍，转录逐字节相同。

**4.4 页面**：`page` 写一个自包含 HTML（无外部资源、不 fetch，双击即开），内联一份 JSON
（`<script type="application/json" id="trace">`；给了 `--trace` 就再写一份同样的文件）：

- `total`、`ticks`：出现过的键（键文件里的 ∪ 操作里加过的）按升序排好；`total ≤ 2000` 全给，
  再多就等距取 2000 个（首尾必在）当刻度。
- `ranges`：每次 `range` 的 `seq`（有效操作行号，从 1 起）、`mode`、`lo`、`hi`、`count`，以及 `i0`、`i1`
  ——命中键在 0..`total`-1 全序里的首、末下标（`ticks` 只是画刻度用的抽样），空结果两者为 `null`。
- `stale`：每个失效时刻的 `seq`、`op`、`key`（只记第一次让遍历失效的那一下）。

页面要画：① 键轴与刻度；② 每次 `range` 一条色带，标 `seq`、`mode`、两端与 `count`（空结果也要有标记）；
③ 每个失效时刻一条竖线，旁写 `op` 与键。位置与数字只能来自 JSON，不许重算语义；配色与交互自定。

## 5. 性能与验收口径

`samples/keys/scale-1m.keys` 有 1 000 000 个键，`samples/expected-budget.txt` 是门槛与跑法。测试机
Windows + Python 3.13 单线程：`scale-1m` 端到端（读键、建索引、跑完操作、写转录）≤ 6 秒、峰值
内存 ≤ 512 MiB；其余样例每对 ≤ 2 秒；页面小样例 ≤ 2 秒。

1. **环境**：Python 3.13+、只用标准库；无构建、无网络、无第三方依赖，命令在仓库根直接跑。
2. **期望**：`run` 对每对样例的输出与 `samples/expected/<名>.out` 逐字节相同。
3. **边界**：四种开闭、`lo == hi`、`lo > hi`、边界压线，结果与期望一致。
4. **遍历**：顺序与 `end`、失效时刻、错误码、重开后的状态按第 2、3 节。
5. **性能与确定性**：按预算，超出即不合格；跑两遍的转录与页面逐字节相同，换 `PYTHONHASHSEED` 也一样。
6. **页面**：结构齐全、无外部资源；手改 JSON 里的 `count`、`i0`/`i1`、`stale` 再刷新，页面跟着变。
7. **测试**：`python -m unittest` 通过，用例只读 `samples/`，只用标准库。

## 6. 样例说明

`samples/keys/<名>.keys` + `samples/scripts/<名>.ops` → `samples/expected/<名>.out`，三者同名一一对应；
`samples/notes.md` 只是现场记录，不参与判定。

| 名 | 键集合 | 盯的是什么 |
| --- | --- | --- |
| `dense` | 12 个连续短键，乱序 | 排序（`d1<d10<d2`）、反复覆盖、删不存在的键、走完遍历 |
| `boundary` | 60 个相邻键 | 开闭压线、单点区间、`lo>hi`、边界在键上或键外 |
| `sparse` | 8 个稀疏键（含大小写与汉字） | 码点序（`Z<a`、`波<阿`）、跨大缝隙、空区间、删除后重查 |
| `longkey` | 4096 字符级长键，前缀嵌套 | 极端长键、前缀序、长键上的范围与覆盖 |
| `mutate` | 6 个短键 | 遍历中允许的操作、三种失效、错误码、失效后重开 |
| `scale-1m` | 1 000 000 个键 | 建索引与范围查询的时限、顺序、确定性 |

## 7. 待补的文档

- 隐藏用例只在评测侧跑，读的也是 `samples/`。
- 页面配色、字号、一行多少条色带自定；只验收结构与数据来源。
- 内部模块划分、命名、日志与 `var/` 中间文件自定；错误码只有 `E_WALK_OPEN`、`E_NO_WALK`、`E_ITER_STALE`。
- 键的规范化、持久化、并发、非文本键在范围外；`samples/` 之外的数据现场自备。
